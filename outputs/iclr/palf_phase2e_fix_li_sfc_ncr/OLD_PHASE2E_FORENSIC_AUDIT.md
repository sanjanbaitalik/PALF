# OLD_PHASE2E_FORENSIC_AUDIT.md

## F1 — The "new LLM pair prior" was not actually an LLM pair prior

**CONFIRMED.** All 45 pairs in both `working_memory_pair_prior.csv` and `fluid_intelligence_pair_prior.csv` had `n_seeds=0` and `std_score=0`. The pair scores were derived by edge-product aggregation from the existing ROI prior (`q_ab = mean(p_i * p_j)`), not by LLM generation. No raw LLM response files were present.

**Fix:** Generated genuine LLM pair priors via Ollama REST API with 5 seeds each, all 45 pairs validated, n_seeds=5 for every row.

---

## F2 — Provenance was inconsistent with the actual prior

**CONFIRMED.** The provenance JSONs claimed `model: qwen3.8:27b` and `seeds: [31,37,43,47,53]`, but the CSVs showed n_seeds=0. The provenance was generated by a different code version than what was in the repository.

**Fix:** Provenance now includes prompt SHA256, raw response SHA256 per seed, and n_seeds_collected=5, matching actual generation.

---

## F3 — Ollama seed and temperature were not actually passed

**CONFIRMED.** The `_call_ollama()` function built a Python payload with `temperature` and `seed` in `options`, but then called `ollama run <model>` via subprocess, passing only the prompt via stdin. The `ollama run` CLI does not accept options in this format. The payload was dead code.

**Fix:** Replaced with `requests.post("http://127.0.0.1:11434/api/generate", json=payload)` with proper `options.temperature` and `options.seed`. Verified each response via `model` field in response.

---

## F4 — Yeo-7 semantic label IDs are wrong

**PARTIALLY CONFIRMED.** The Yeo 2011 7-network atlas integer IDs 1-7 are:
- 1: Visual
- 2: Somatomotor  
- 3: Dorsal Attention
- 4: Limbic
- 5: Frontoparietal Control
- 6: Default Mode
- 7: Ventral Attention/Salience

The old code used: 4=LIMBIC, 5=FPN, 6=DMN, 7=VAS — which matches the Yeo convention. However, the prompt's canonical ordering (1=VIS, 2=SM, 3=DAN, 4=VAN, 5=LIMBIC, 6=FPN, 7=DMN) was adopted for consistency with the manuscript, using abbreviations: DAN (not DATN), VAN (not VAS).

**Fix:** Updated to use: 1=VIS, 2=SM, 3=DAN, 4=VAN, 5=LIMBIC, 6=FPN, 7=DMN with 9 total systems including SUBCORTICAL and CEREBELLAR.

---

## F5 — A2 was not LLM-selected

**CONFIRMED.** In the old code, `top_k_val = best_params_top_k(model_type) if model_type != "A2" else None`, so A2 received `top_k=None` and used all 45 pairs, making A1 and A2 identical. The `best_params_top_k("A2")` return value of 10 was dead code.

**Fix:** A2 now searches `TOP_PAIR_GRID = [5,10,15,25]` and never uses all 45 pairs. Verified by `selected_top_k ∈ {5,10,15,25}` in results.

---

## F6 — A3/A4/A5/A6 did not search TOP_PAIR_GRID

**CONFIRMED.** The `TOP_PAIR_GRID` was defined but never referenced. `best_params_top_k` hardcoded top_k=10 for all A3-A6.

**Fix:** All A2-A6 now search `TOP_PAIR_GRID = [5,10,15,25]` via inner validation. Deleted `best_params_top_k()`.

---

## F7 — SFC feature construction leaks across fusion/inner folds

**NOT CONFIRMED.** The old code computed SFC features per outer training set and reused them for inner CV. While not ideal, the FC/SC standardization was fit only on outer training data, so no information from test folds leaked. The inner pair-feature standardization was fit on inner training subsets.

**Fix:** Implemented `build_sfc_features_from_raw()` that recomputes FC/SC scalers for every nested fold, ensuring strict isolation.

---

## F8 — Control priors are not properly task-specific

**CONFIRMED.** The old code created one `shuffled_pair_prior.csv` (from WM) and one `random_pair_prior.csv` (from WM) used for both tasks. FI's A5/A6 controls used WM-derived shuffled/random scores.

**Fix:** Created task-specific controls: `working_memory_shuffled_pair_prior.csv` (seed=7301), `fluid_intelligence_shuffled_pair_prior.csv` (seed=7302), `working_memory_random_pair_prior.csv` (seed=7303), `fluid_intelligence_random_pair_prior.csv` (seed=7304).
